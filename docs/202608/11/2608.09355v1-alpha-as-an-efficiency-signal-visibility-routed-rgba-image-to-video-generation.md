## 摘要
RGBA 视频将 RGB 外观与 alpha 通道相结合，使得动画资源能够应用于任意背景，这在游戏行业中被广泛使用。然而，为游戏生成高质量的 RGBA 动画仍然面临两个挑战。首先，现有的大多数 RGBA 视频数据集以逼真内容为主，游戏资产的覆盖有限。其次，传统的先生成后抠像（generate-then-matte）流程仅在 RGB 合成后估计 alpha，导致半透明区域常被背景模糊，产生不稳定的抠像输出。近年来，许多方法开始联合建模 RGB 和 alpha，但现有方法大多基于文本条件，且在效率和质量上仍存在问题。为解决这些挑战，我们引入了 GameAlpha-2.4K，一个包含 2400 个剪辑的游戏风格 RGBA 视频数据集，通过适合抠像的合成、多假设 alpha 恢复和基于合成的质量门控构建。利用该数据集，我们训练了一个参考条件 RGBA 视频生成器，可单次通过同时生成 RGB 帧和 alpha 遮罩。为提高效率，我们提出了一种可见性路由器，在早期阶段识别透明 token，并跳过其在后续 DiT 更新中的计算，同时 x_0-lock 引导这些 token 沿着原始流匹配调度走向自预测终点。我们的模型在 FVD 上优于传统两阶段流程，且可见性路由器在最后两个 DiT 去噪步骤中跳过了 35% 的 token 评估，与密集推理相比提供了 1.2 倍的后端加速，且质量下降可忽略不计。

## Abstract
RGBA videos combine RGB appearance with an alpha channel, enabling animated assets to be applied across arbitrary backgrounds, which are heavily used in gaming industry. However, generating high-quality RGBA animations for games remains challenging for two reasons. First, most existing RGBA video datasets are dominated by photorealistic content, with limited coverage of game assets. Second, the traditional generate-then-matte pipelines estimate alpha only after RGB synthesis, so semi-transparent regions are often blurred by background, resulting in unstable matting outputs. More recently, many methods have begun to model RGB and alpha jointly, but existing approaches are mostly text-conditioned, and still have unresolved issues in efficiency and quality. To address these challenges, we introduce GameAlpha-2.4K, a 2.4K-clip game-style RGBA video dataset built with matte-friendly synthesis, multi-hypothesis alpha recovery, and compositing-based quality gates. Using this dataset, we train a reference-conditioned RGBA video generator that jointly produces RGB frames and alpha mattes in a single pass. To improve efficiency, we propose a visibility router that identifies transparent tokens in an early stage and bypasses their later DiT updates, while x_0-lock guides them along the original flow-matching schedule toward self-predicted endpoints. Our model obtains lower FVD than traditional two-stage pipelines, and the visibility router skips 35% of token evaluations in the final two DiT denoising steps, providing a 1.2x backbone speedup with negligible quality degradation compared to dense inference.

## 2. 论文提出的方法论

### 2.1 核心思想

- 构建一个**参考条件（reference-conditioned）的单阶段 RGBA 视频生成器**，一次推理同时输出 RGB 帧与 alpha 遮罩。
- 利用生成的 alpha 预测结果，在去噪早期识别出最终将保持完全透明的 token，并通过**可见性路由器（Visibility Router）** 跳过这些 token 在后半程 DiT 中的更新，配合 **x₀-lock** 机制让被路由的 token 沿原有流匹配轨迹继续前进。

### 2.2 数据集：GameAlpha-2.4K

- 规模：约 2,400 个游戏风格 RGBA 视频剪辑（实际 2,395 个，232.8K 帧，960×960 原生分辨率）。
- 构建流程分为四阶段，每阶段均设质量门控：
  1. **分布控制采样**：对实体（7类）、装备（7类）、动作（5类）、风格（23类）、视角（7类）进行组合采样，用硬规则剔除不合理组合，并以接受率反馈更新采样权重，避免类别漂移。
  2. **Matte 友好参考合成**：固定大规模 T2I 模型生成单一主体、无内容背景的参考图；VLM 门控检查属性、取景、背景污染与外部投影，失败则生成修复指令并重新生成（最多 3 次）；BiRefNet 提取参考 alpha。
  3. **受控视频合成与 Raw-Video 门**：参考 RGB 驱动固定 I2V 模型生成视频；门控检查主体一致性、动作方向、外部阴影、碎片、背景内容等，避免无效片段进入抠图阶段。
  4. **多假设 alpha 恢复与分阶段审计**：对每个保留片段用 BiRefNet（帧级+光流时序稳定）、SAM3（视频分割）、MatAnyone2（视频抠像）生成三种完整 alpha 假设，由多模态评估器基于合成质量选择完整序列（81% 来自 BiRefNet，13% SAM3，6% MatAnyone2），再经 VLM 全量和人工十分之一抽检。
- alpha 统计：70.1% 像素完全透明，27.8% 完全不透明，中间软带仅 2.2%——这是数据集的一大特征，也是 VAE 需额外混合训练数据的原因。

### 2.3 模型架构：单遍联合生成

- 采用 **merged RGB-A VAE**（借鉴 Wan-Alpha）：将 RGB 与三通道复制的灰度 alpha 共同编码进 Wan 原生 16 通道潜空间，不增加任何 DiT token 数量或 alpha 专属分支。
  - 条件构造：将 RGBA 参考图作为首帧潜变量锚点，后续帧为零；与四通道首帧 mask 拼接为 20 通道条件 y，再与 16 通道目标 x_t 拼接为原始 36 通道 DiT 输入，完整保留 Wan-I2V 的既有接口。
  - 训练分两阶段：Stage 1 在 GameAlpha 训练集 + VideoMatte240K 上学习 RGB-A 潜空间契约（只训练 merge 模块 M 与解码器 LoRA，冻结预训练 encoder/base decoder）；Stage 2 用 DoRA 适配 Wan2.1-I2V-14B 的 DiT，训练 flow matching 目标（保持空间均匀的调度加权损失，不用 alpha 重新加权——消融显示这反而更好）。

### 2.4 可见性路由推断

- **理论判据**：由合成方程 C = αR + (1−α)B，当最终 α=0 时 RGB 的误差对合成结果没有直接贡献。问题转化为：在去噪早期预测哪些 token 最终完全透明。
- **透明度探针**：在第二次 DiT 评估后，用离线拟合的 logistic regression 探针读取 x̂₀ 的 2×2×16 潜空间 patch，输出透明度 logit ℓⱼ。
- **保守安全策略**：
  - 对预测非透明的支撑区域做空间膨胀（r_s=2）与时间扩展（r_t=1），并始终保持首帧激活；
  - 候选 token 不足 10% 或不确定 token 超过 15% 时，退回完全密集推理（bit-exact）。
- **x₀-lock**：对路由 token 存储第 2 步的 clean 端点 x*₀，后续步骤按 v = (x_t − x*₀)/σ_k 直线推进，精确沿原始流匹配调度移动，无需改变全局噪声时间表。
- **局部再激活与 Cache-KV**：第一次稀疏评估后，根据新的 active token clean 估计更新支撑区域，对扩展到的路由 token 重新激活；缓存路由 token 在第 2 步的 K/V，使 active token 的注意力仍能看到路由 token 的上下文（Drop-KV 则丢弃该上下文以换取更高加速）。

## 6. 论文的主要结论与发现

- 单阶段联合生成 RGB 与 alpha 优于先生成后抠图：在 FVD、MAD、运行时间上全面占优（相对最强两阶段基线 FVD 降低约 21%）。
- Alpha 可作为任务原生的效率信号：早期 clean estimate 中已包含足够的最终透明度信息（第 2 步 AUROC 0.9952），路由器可有效识别最终透明 token。
- 可见性路由能以极小质量代价换取可观的推理加速：跳过最后两步中 35% 的 token 评估，获得 1.2× DiT 骨干加速（Drop-KV 达 1.3×），FVD 仅从 172.3 升到 174.4。
- 再激活机制不可或缺：若不重新激活被后续前景扩展覆盖的 token，FVD 从 174.4 恶化至 537.2。
- 训练阶段对透明区域进行降权并无益处（FVD 从 172.3 升至 185.8），空间均匀的 flow-matching 目标更合适。
- 跨域测试显示模型在领域偏移下仍能保持优势，且 dense fallback 与 reactivation 是有效的安全机制。

## 7. 优点

- **理论动机清晰**：从合成方程 C=αR+(1−α)B 严格推导出“alpha 为零处 RGB 对合成无贡献”的判据，将透明度转化为可操作的效率信号，而非通用的注意力/显著度启发式。
- **数据集构建细致**：多假设 alpha 恢复、接受率反馈采样、分阶段可修复门控、光流稳定 BiRefNet 等设计，显著提高了监督质量；并披露了完整的数据集统计（透明度分布、类别覆盖、接受漏斗）。
- **方法保持兼容性**：merged RGB-A 潜空间不增加 token 数量、不新增 DiT 分支，保留预训练 I2V 接口；可见性路由器不改动去噪计划表和模型参数，与步骤蒸馏（LightX2V）等正交加速技术兼容。
- **工程严谨**：路由决策前有 bit-exact dense fallback；x₀-lock 保证路由 token 不偏离全局噪声调度；Cache-KV 保留完整注意力上下文，再激活机制修正早期错误。
- **实验充分**：指标覆盖质量、运动、alpha 精度、人类感知、效率等多个维度；消融设计能清晰区分信号质量、自适应能力、再激活和上下文保留各自的贡献。

## 8. 不足与局限

- **加速上限受限**：二进制路由器只针对“完全透明”（α≤0.05）的 token 生效；对半透明区域（软边、发光、粒子）无法跳过，对前景密集的 clip 几乎没有加速空间（实验显示评估

“对前景密集的 clip 几乎没有加速空间（实验显示评估中部分前景饱和的剪辑中位 token 节省接近 0，加速比趋近 1.0×）”。此外，路由器以 2×2×16 的 patch 为粒度预测透明度，对于细小镂空、发丝等亚 patch 结构只能做空间膨胀近似，可能遗漏小面积透明区域或误伤不透明区域，导致质量与收益的折衷不够完美。

- **半透明区域无法利用效率信号**：合成方程对 α 在 (0,1) 的软边区域并不构成“可跳过”的判据，因此所有半透明 token 仍需参与全部计算。而游戏资产中毛发、发光特效、运动模糊恰恰是高频使用且计算昂贵的部分，这限制了路由在真实工作负载上的加速上限。

- **依赖早期预测质量**：路由决策在去噪第 2 步做出，此时 clean estimate 尚不精确。对于快速运动、大幅遮挡或参考图与目标风格差异较大的输入，早期透明度预测可能出现偏差。虽然保守策略（膨胀、fallback、再激活）能在一定程度上修正，但一旦触发 dense fallback，路由收益消失；而若未触发 fallback 仅靠再激活，后发的前景扩展仍可能覆盖原本透明的 token，导致不完全的视觉瑕疵。

- **数据集构建成本与真值偏差**：GameAlpha-2.4K 的构建流程依赖多个闭源模型（T2I、I2V、VLM、多目标分割器），pipeline 复杂、成本高，且可复现性受限于这些服务的可用性。更关键的是，数据集的 alpha 并非渲染真值，而是从 BiRefNet/SAM3/MatAnyone2 三种提取结果中“择优”得到的。这种提取器共识只能近似真实透明度，尤其在极端半透明（雾效、光晕、反射）场景下可能系统性偏离物理真值，从而限制模型学习真实 matte 能力的上限。

- **对照范围局限**：论文将单阶段联合生成与两阶段“生成+抠图”进行对比，这是合理的系统级对比。但缺少与其他“联合生成 RGB-A”方法（如并行训练的 GAN 或 VAE 类方法、以及文本条件 RGBA 生成模型）的直接对比，因为当前缺乏公开可用的参考条件联合生成基线。因此，无法严格证明“单阶段优于两阶段”这一结论在更广的方法族中是否普适。

- **参考图条件导致的功能边界**：模型只能跟随给定的 RGBA 参考图进行生成，不支持文本控制、草图控制或多视角布局控制。对于游戏资产生产流程中常见的“仅给定文字描述创建动画”或“从单一静态图生成多视图动画”等需求，模型无法直接支持，应用范围受限。

- **端到端收益有限与工程细节不透明**：路由在 DiT 骨干上提供 1.2×–1.3× 加速，但端到端 104.8s 的耗时中解码与 VAE 后处理占据相当比例，因此实际用户体验到的提升小于骨干加速比。另外，论文未披露 GPU 型号、探针训练细节、DoRA 超参数范围等，虽公开了核心代码思路，但复现仍需一定工程成本。

## 9. 总评与展望

总体而言，这篇论文在问题定位、方法设计和实验验证上都表现出色。它将一个传统的“视觉质量”问题（alpha matte）重构为“计算效率”问题，提出了可解释、可证明的可见性路由机制，并配套贡献了高质量数据集和稳健的工程实现。即使存在加速上限和数据集真值偏差等局限，其核心思想——利用任务结构信息而非语义显著性来指导计算分配——具有较高的普适性和启发价值，可推广到其他良定义合成场景（如深度合成、光流合成或分割图引导生成）。

未来可能的发展方向包括：

1. **扩展软边 token 路由**：对 α∈(0,1) 的 token 设计近似更新规则（如空间低频替代、轻量网络预测），以突破当前仅二值跳过的加速瓶颈。
2. **与其他推理加速技术正交叠加**：与步骤蒸馏、缓存复用、量化或 early-exit 结合，探索在保证质量前提下更大比例的 DiT 计算削减。
3. **更强大的联合 matte 学习**：引入渲染真值数据或合成 RGBA 视频，提升模型对半透明的物理建模精度；或将参考条件扩展为文本+姿态+语音等多模态控制。
4. **开源数据集与权重**：推进 GameAlpha-2.4K 和模型权重的开放，以吸引社区共建更丰富的数据生态与更深的对比实验，验证结论的稳健性。

综上，本文是“以任务原生信号指导高效生成”方向上的一项扎实且有影响力的工作，其方法论创新与工程实现均值得借鉴。
